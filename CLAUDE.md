## Commands

### Local Development

```bash
# Start PostgreSQL and Redis (required before running the server)
make dev-up

# Stop local infrastructure
make dev-down

# Generate Swagger docs and run the API server
make dev-run

# Run the server directly (without regenerating Swagger)
go run ./cmd/api/main.go
```

### Testing

```bash
# Run all tests with coverage report (enforces 80% threshold)
make test

# Run a specific package
go test ./internal/app/service/bookmark/...
go test ./internal/app/handler/user/...
go test ./internal/api/middleware/...

# Run tests verbosely
go test -v ./...
```

### Code Generation

```bash
# Regenerate all mocks (uses go generate)
make mock-gen

# Regenerate Swagger documentation
make swag-gen
```

### Database Migrations

```bash
# Apply all pending migrations
make migrate

# Create a new migration file pair
make new-schema name=add_some_table
```

### Docker

```bash
make docker-up       # Start production stack
make docker-down     # Stop production stack
make docker-build    # Build app and migration Docker images
make docker-release  # Build and push images to Docker Hub
```

### RSA Keys (JWT)

```bash

make generate-rsa-key
```

## Architecture

This is a Go REST API using **Gin** with a clean layered architecture:

```
Request → Middleware (JWT / RateLimit) → Handler → Service → Repository → PostgreSQL / Redis
```

### Layer Responsibilities

- **`internal/api/`** — Gin engine setup, route registration, middleware wiring, custom validators
- **`internal/api/middleware/`** — JWT authentication (`jwtauth.go`) and IP-based rate limiting (`ratelimit.go`)
- **`internal/app/handler/`** — HTTP request parsing, response formatting; one subdirectory per feature
- **`internal/app/service/`** — Business logic; each feature has an interface + implementation
- **`internal/app/repository/`** — Data access via GORM (PostgreSQL) or Redis; one subdirectory per feature
- **`internal/app/model/`** — GORM domain entities (`User`, `Bookmark`, etc.)
- **`internal/infrastructure/`** — Composition root: `CreateAPI()` bootstraps DB, Redis, JWT providers, and passes them into `api.New()`
- **`pkg/`** — Shared, reusable packages: `jwtutils`, `utils` (code gen, password hashing), `common` (error/response helpers), `validators`, `encoding` (Base62), `logger`, `sqldb`, `redis`
- **`migrations/`** — Sequential SQL migration files (managed by `golang-migrate`)

### Key Wiring Points

- **`internal/infrastructure/api.go`** — `CreateAPI()` is the composition root; instantiates all dependencies and passes them to `api.New()`
- **`internal/api/api.go`** — `registerHandlers()` wires repos → services → handlers; `registerMiddlewares()` sets up JWT auth and rate limiter; `registerRoutes()` attaches everything to Gin routes

### Feature Layout Pattern

Each feature (bookmark, user, link, healthcheck, random_code_gen) follows the same structure:

```
internal/app/
├── handler/<feature>/       # HTTP handler + interface
├── service/<feature>/       # Business logic + interface + mocks/
└── repository/<feature>/    # DB/Redis access + interface
```

Mocks live in `service/<feature>/mocks/` and `repository/<feature>/mocks/`, generated by `go generate`.

### Route Groups

```
GET  /health-check               # public, no rate limit
GET  /swagger/*any               # public, no rate limit

/v1  (rate-limited: 20 req / 10s per IP)
  GET  /generate-password
  POST /links/shorten
  GET  /links/redirect/:code
  POST /users/register
  POST /users/login

/v1  (JWT-protected)
  GET  /self/info
  PUT  /self/info
  POST /bookmarks
  GET  /bookmarks
  PUT  /bookmarks/:id
  DELETE /bookmarks/:id
```

### Caching Pattern

The bookmark service uses a **decorator pattern** for Redis caching:

```go
bookmarkSvc := bookmarkService.NewBookmarkService(bookmarkRepo)
bookmarkSvcWithCache := bookmarkService.NewBookmarkServiceWithCache(bookmarkSvc, redisCache)
```

`NewBookmarkServiceWithCache` wraps the base service and satisfies the same interface.

### Rate Limiting

Implemented in `internal/api/middleware/ratelimit.go` and backed by `internal/app/repository/ratelimit/`.

- **Window**: 10 seconds (`RateLimitInterval`)
- **Max requests**: 20 per window per IP (`RateLimitMaxCount`)
- **Redis key format**: `rate_limit:<client_ip>`
- Applied via `v1.Use(allMiddlewares.rateLimitMiddleware.RateLimit())` on the `/v1` route group

### Auth

- JWT uses RSA keys (`private_key.pem` / `public_key.pem`); generate with `make generate-rsa-key`
- JWT middleware is in `internal/api/middleware/jwtauth.go` and applied to the `v1Private` route group
- Protected routes require `Authorization: Bearer <token>` header
- JWT utilities (generator, validator, mocks) live in `pkg/jwtutils/`

### Custom Validation

Custom Gin validators (e.g., `password_strength`) are registered once at startup via `sync.Once` in `api.registerValidations()`. Add new validators to `pkg/validators/`.

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `APP_PORT` | `:8080` | HTTP listen port |
| `SERVICE_NAME` | `bookmark_service` | Identifier in health check |
| `INSTANCE_ID` | auto UUID | Per-instance identifier |
| `APP_HOST_NAME` | `localhost:8080` | Used in Swagger host |
| `DB_HOST` | `localhost` | PostgreSQL host |
| `DB_PORT` | `5432` | PostgreSQL port |
| `DB_USER` | `admin` | PostgreSQL user |
| `DB_PASSWORD` | `admin` | PostgreSQL password |
| `DB_NAME` | `bookmark_service` | PostgreSQL database |
| `REDIS_ADDR` | `localhost:6379` | Redis address |
| `REDIS_PASSWORD` | `""` | Redis password |
| `REDIS_DB` | `0` | Redis database index |

## Testing Notes

- Integration tests live in `internal/test/integration_test/` and use `miniredis` (Redis) and SQLite for isolation — no real infrastructure needed
- Shared test fixtures are in `internal/test/fixture/`
- Coverage threshold is **80%**; excluded paths: `infrastructure|mocks|vendor|test|docs|main.go|config.go|client.go`
- Run `make test` to get the full HTML coverage report at `coverage/coverage.html`
